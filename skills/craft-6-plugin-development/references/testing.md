# Verifying a plugin in its workbench

Every feature must be exercised in a real Craft 6 install the way a user reaches it. The plugin's workbench is that install: an Orchestra Testbench app generated by Testbench itself, with Craft installed by a seeder. craftcms/cms uses the same skeleton-based layout.

## Workbench setup

With the plugin's `composer.json`, `src/Plugin.php` and `database/migrations/Install.php` in place:

1. Add the dev dependencies and Composer plugin permissions to `composer.json`, then install:

   ```json
   "require-dev": {
       "orchestra/testbench": "^11.0",
       "pestphp/pest": "^5.0"
   },
   "autoload-dev": { "psr-4": { "Acme\\Shortlinks\\Tests\\": "tests/" } },
   "minimum-stability": "dev",
   "prefer-stable": true,
   "config": {
       "allow-plugins": {
           "craftcms/plugin-installer": true,
           "pestphp/pest-plugin": true,
           "php-http/discovery": true
       }
   }
   ```

   ```bash
   composer update -W
   ```

2. Generate the workbench: `vendor/bin/testbench workbench:install --devtool --no-interaction`. It writes `testbench.yaml`, `workbench/` (routes, seeders, a service provider) and the `clear`, `prepare`, `build` and `serve` Composer scripts, and adds `Workbench\…` autoload entries. Delete `workbench/app/Models/`, `workbench/database/factories/` and the `Workbench\Database\Factories\` autoload entry; Craft has its own user model.

3. Replace `testbench.yaml` with:

   ```yaml
   laravel: '@testbench'

   providers:
     - Inertia\ServiceProvider

   env:
     - APP_NAME="Shortlinks Workbench"
     - APP_URL=http://127.0.0.1:8000
     - AUTH_MODEL=CraftCms\Cms\User\Models\User
     - CRAFT_EDITION=pro
     - DB_CONNECTION=sqlite
     - CACHE_STORE=file
     - SESSION_DRIVER=file
     - QUEUE_CONNECTION=database

   seeders:
     - Workbench\Database\Seeders\DatabaseSeeder

   workbench:
     start: /admin
     user: 1
     install: false
     discovers:
       web: true
     sync:
       - from: storage
         to: workbench/storage
         reverse: true
       - from: workbench/resources/views
         to: resources/views
   ```

4. Replace the generated `build` script in `composer.json` (keep `clear`, `prepare` and `serve`) and add `test`:

   ```json
   "build": [
       "@php vendor/bin/testbench package:create-sqlite-db --ansi",
       "@php vendor/bin/testbench vendor:publish --tag=craftcms-assets --force --ansi",
       "@php vendor/bin/testbench db:seed --class='Workbench\\Database\\Seeders\\DatabaseSeeder' --force --ansi"
   ],
   "test": "@php vendor/bin/pest"
   ```

   Quote the seeder class so the shell keeps its backslashes.

5. Replace `workbench/database/seeders/DatabaseSeeder.php`:

   ```php
   <?php

   declare(strict_types=1);

   namespace Workbench\Database\Seeders;

   use CraftCms\Cms\Cms;
   use CraftCms\Cms\Support\Facades\Plugins;
   use Illuminate\Database\Seeder;
   use Illuminate\Support\Facades\Context;
   use RuntimeException;

   /** Installs Craft and the plugin, then demo content. Safe to rerun. */
   class DatabaseSeeder extends Seeder
   {
       public function run(): void
       {
           if (! Cms::isInstalled()) {
               $status = $this->command->call('craft:install', [
                   '--username' => 'admin',
                   '--password' => 'password123',
                   '--email' => 'admin@example.test',
                   '--siteName' => config('app.name'),
                   '--siteUrl' => '$APP_URL',
                   '--language' => 'en-US',
                   '--no-interaction' => true,
               ]);

               if ($status !== 0) {
                   throw new RuntimeException('Craft installation failed.');
               }

               Context::forgetHidden('craft.info');
               Context::forgetHidden('craft.isInstalled');
           }

           if (! Plugins::isPluginInstalled('shortlinks')) {
               Plugins::installPlugin('shortlinks');
           }

           Plugins::createPlugin('shortlinks')->publishFrontendAssets();

           // Demo content (sections, entries, users, settings) goes here; see the fixtures below.
       }
   }
   ```

6. Replace `workbench/routes/web.php` with `Route::redirect('/', '/admin');` plus any test routes you need, and set up Pest ([Automated tests](#automated-tests)).

7. Add `/vendor`, `/node_modules`, `/.phpunit.cache` and `/workbench/storage` to `.gitignore`, then run it:

   ```bash
   composer build                     # Craft (admin / password123) and the plugin, in SQLite
   vendor/bin/testbench craft:plugin:list
   composer serve                     # runs build, then http://127.0.0.1:8000/admin
   composer test
   ```

Run `composer serve` under your environment's service manager if you have one; a backgrounded `&` process may be killed with your shell.

| Craft project | Workbench |
| --- | --- |
| `php artisan …` | `vendor/bin/testbench …` (from the plugin root) |
| `.env` | `env:` in `testbench.yaml` |
| `storage/logs/laravel.log` | `workbench/storage/logs/laravel.log` (a symlink, created on `serve`) |
| `routes/web.php` (site routes) | `workbench/routes/web.php` |
| `resources/views/` (site templates) | `workbench/resources/views/` (symlinked into the skeleton on `serve`) |
| `database/database.sqlite`, `config/craft/` (project config, plugin config overrides), `public/` | Inside Testbench's skeleton, `vendor/orchestra/testbench-core/laravel/…` |

- The workbench runs inside Testbench's skeleton app, `vendor/orchestra/testbench-core/laravel`. Every `composer dump-autoload` (and so every `composer update`) purges the skeleton's database; `composer build` or `composer serve` reinstalls. Seed anything you need to keep in `DatabaseSeeder`, using the fixtures below, so it comes back in one command.
- Plugin code edits are live; there is no package to reinstall. After changing `composer.json` (autoload, `extra`), run `composer dump-autoload`.
- Render site templates with Craft, not Laravel's view finder: `Route::get('demo', fn () => \CraftCms\Cms\template('demo'));`. `Route::view()` passes an absolute path that Craft's Twig loader rejects.
- `APP_URL` must match the port you serve on, or generated URLs and redirects point elsewhere. The primary site's base URL is `$APP_URL`.
- `testbench serve` is single-threaded by default. A request that calls back into the same server (for example a job fetching a site URL) deadlocks; add `PHP_CLI_SERVER_WORKERS=4` to `env:` if you need that.

## Running PHP inside the app

Write the code to a file, then:

```bash
vendor/bin/testbench tinker --execute="include '/tmp/check.php';"
```

`tinker /tmp/check.php` opens an interactive prompt and hangs without a terminal. Keep scratch scripts outside the plugin repository.

## Control panel requests

```bash
J=/tmp/jar
curl -s -c $J -b $J -o /dev/null http://127.0.0.1:8000/_workbench/login/1   # Testbench logs the session in as user 1 (admin)
curl -s -b $J -c $J http://127.0.0.1:8000/admin/shortlinks -o page.html -w '%{http_code}\n'
xsrf() { awk '$6 == "XSRF-TOKEN" {print $7}' "$1" | tail -1 | python3 -c 'import sys, urllib.parse; print(urllib.parse.unquote(sys.stdin.read().strip()))'; }
TOKEN=$(xsrf $J)                                                             # re-read before each POST; it rotates
curl -s -b $J -c $J -X POST http://127.0.0.1:8000/admin/shortlinks \
  -H "X-XSRF-TOKEN: $TOKEN" -H 'Accept: application/json' \
  -d code=abc -d destination=https://example.com
```

- `/_workbench/login/<userId>` and `/_workbench/logout` come from Testbench's workbench (`workbench.user` in `testbench.yaml`); `/_workbench` logs in as that user and opens `start`. They only exist in the workbench, so don't test real login with them. In a browser (agent-browser), open `http://127.0.0.1:8000/_workbench` the same way.
- Without the token: `419`. Not logged in: expect `302` to `/admin/login`. A `200` for a guest means the route is missing `auth`.
- `Accept: application/json` makes `RespondsWithFlash` and validation return JSON (422 with `errors` on validation failure).
- Plugin settings: `GET /admin/settings/plugins/<handle>` renders the form as JSON inside `<script data-page="app" type="application/json">`. Save with `POST /admin/settings/plugins/<handle>`, `Content-Type: application/json`, body `{"settings": {...}}`. Expect `200` and the values under `plugins.<handle>.settings` in `config/craft/project/project.yaml`.
- Every CP page is an Inertia page, including Twig `pageTemplate()` pages (they are "bridged": their HTML is embedded in the props). So rendered markup appears JSON-escaped inside `<script data-page="app" type="application/json">`, and a plain `grep '<p id="x">'` finds nothing. Extract and decode the props:

```bash
python3 -c 'import sys,re,json,html; m=re.search(r"<script data-page=\"app\" type=\"application/json\">(.*?)</script>", sys.stdin.read(), re.S); print(json.dumps(json.loads(html.unescape(m.group(1)))["props"], indent=1))' < page.html
```

  Or grep the decoded text. For a real rendering check, load the page in a browser (agent-browser, Playwright) if one is available.

## Front-end requests

For a front-end form, put a test template in `workbench/resources/views/` (the workbench's site template root), route to it in `workbench/routes/web.php` with `Route::get('form', fn () => \CraftCms\Cms\template('form'))`, then GET it, extract `_token`, and POST back.

## Content fixtures

Run these with `vendor/bin/testbench tinker --execute='include "/tmp/fixture.php";'`.

The same code works at the end of the workbench seeder (demo content) and inside Pest tests. Build fixtures through Craft's public services (`Sections`, `EntryTypes`, `Elements`, `UserPermissions`) as below. `CraftCms\Cms\Database\Factories\…` (`UserFactory` and friends) are in Craft's `autoload-dev`, so a plugin can't use them.

The admin account is user id 1: `admin` / `password123` in the workbench, `craftcms` / `craftcms2018!!` in `PluginTestCase` (log in as it with `$this->actingAs(\CraftCms\Cms\User\Models\User::find(1))`).

A channel section with an entry type that has a title field, and one entry:

```php
<?php

use CraftCms\Cms\Entry\Data\EntryType;
use CraftCms\Cms\Entry\Elements\Entry;
use CraftCms\Cms\Entry\EntryTypes;
use CraftCms\Cms\FieldLayout\FieldLayout;
use CraftCms\Cms\FieldLayout\LayoutElements\TitleField;
use CraftCms\Cms\Section\Data\Section;
use CraftCms\Cms\Section\Data\SectionSiteSettings;
use CraftCms\Cms\Section\Enums\SectionType;
use CraftCms\Cms\Section\Sections;
use CraftCms\Cms\Support\Facades\Elements;

$type = new EntryType(['name' => 'Article', 'handle' => 'article']);
$type->setFieldLayout(FieldLayout::createFromConfig([
    'type' => Entry::class,
    'tabs' => [['name' => 'Content', 'elements' => [['type' => TitleField::class]]]],
]));
app(EntryTypes::class)->saveEntryType($type) or throw new RuntimeException(json_encode($type->errors()->getMessages()));

$section = new Section(['name' => 'Blog', 'handle' => 'blog', 'type' => SectionType::Channel, 'minAuthors' => 0]);
$section->setEntryTypes([$type]);
$section->setSiteSettings([1 => new SectionSiteSettings(['siteId' => 1, 'hasUrls' => true, 'uriFormat' => 'blog/{slug}', 'template' => 'blog/_entry'])]);
app(Sections::class)->saveSection($section) or throw new RuntimeException(json_encode($section->errors()->getMessages()));

$entry = new Entry(['sectionId' => $section->id, 'typeId' => $type->id, 'siteId' => 1, 'title' => 'Hello world']);
Elements::saveElement($entry) or throw new RuntimeException(json_encode($entry->errors()->getMessages()));
echo $entry->id;   // the canonical entry id
```

Saving an entry also creates a **revision**, which is another row in `entries` (and `elements`) with a higher id. Use the id returned by the save, not `max(id)`. A default `Entry::find()` excludes drafts and revisions; add `->revisions(true)` or `->drafts(true)`, and `->status(null)` for disabled entries, when you need them.

To put a custom field in the layout, add `['type' => \CraftCms\Cms\FieldLayout\LayoutElements\CustomField::class, 'fieldUid' => $field->uid]` to the tab's `elements`.

### Multiple sites

```php
use CraftCms\Cms\Site\Data\Site;
use CraftCms\Cms\Site\Sites;

$sites = app(Sites::class);
$fr = new Site(['name' => 'Français', 'handle' => 'fr', 'language' => 'fr', 'groupId' => $sites->getSiteById(1)->groupId, 'baseUrl' => 'http://127.0.0.1:8000/fr/']);
$sites->saveSite($fr) or throw new RuntimeException(json_encode($fr->errors()->getMessages()));
```

Create the site before the section, and give `setSiteSettings()` one `SectionSiteSettings` per site id.

### Assets

Volumes point at a Laravel disk (`config/filesystems.php`); the starter's `public` disk works after `vendor/bin/testbench storage:link`:

```php
use CraftCms\Cms\Asset\Data\Volume;
use CraftCms\Cms\Asset\Elements\Asset;
use CraftCms\Cms\Asset\Folders;
use CraftCms\Cms\Asset\Volumes;

$volume = new Volume(['name' => 'Images', 'handle' => 'images', 'fsHandle' => 'public', 'hasUrls' => true]);
app(Volumes::class)->saveVolume($volume) or throw new RuntimeException(json_encode($volume->errors()->getMessages()));
$folder = app(Folders::class)->getRootFolderByVolumeId($volume->id);
$asset = new Asset(['volumeId' => $volume->id, 'folderId' => $folder->id, 'filename' => 'social.png', 'tempFilePath' => '/tmp/social.png', 'title' => 'Social image']);
Elements::saveElement($asset) or throw new RuntimeException(json_encode($asset->errors()->getMessages()));
```

Element queries are scoped to the current site. An asset (or entry) id stored in a setting may not exist in every site: look it up with `Asset::find()->id($id)->site('*')->unique()->preferSites([$siteId])->one()`.

Make a test PNG with GD if ImageMagick is missing: `php -r '$i=imagecreatetruecolor(1200,630); imagepng($i,"/tmp/social.png");'`.

## A restricted (non-admin) user

User permissions need the Pro edition, and a CP user needs `accessCp` (plus `accessPlugin-<handle>` if the plugin has a CP section):

```bash
vendor/bin/testbench craft:users:create --email=viewer@example.test --username=viewer --password=password123 --admin=0 --activate=1 --no-interaction
vendor/bin/testbench tinker --execute='$u = \CraftCms\Cms\User\Elements\User::find()->username("viewer")->one(); app(\CraftCms\Cms\User\UserPermissions::class)->saveUserPermissions($u->id, ["accessCp", "accessPlugin-shortlinks", "shortlinks-viewLinks"]);'
ID=$(vendor/bin/testbench tinker --execute='echo \CraftCms\Cms\User\Models\User::where("username", "viewer")->value("id");')
curl -s -c /tmp/viewer.jar -o /dev/null http://127.0.0.1:8000/_workbench/login/$ID
```

## Uninstall and reinstall

```bash
vendor/bin/testbench craft:plugin:uninstall <handle> --force
sqlite3 vendor/orchestra/testbench-core/laravel/database/database.sqlite .tables | tr -s ' ' '\n' | grep <prefix>    # expect nothing
vendor/bin/testbench craft:plugin:install <handle>
```

## Logs

`workbench/storage/logs/laravel.log` (the file name follows the log channel; check the folder if it's missing). A 500 from a JSON request includes `exception` and `message` in the body; read them before guessing.

## Automated tests

Pest runs on Craft's `CraftCms\Cms\Plugin\Testing\PluginTestCase` (Orchestra Testbench). Each test gets a fresh in-memory SQLite database with Craft installed; the base class then registers the plugin from its own `composer.json` and installs and enables it, which runs `database/migrations/Install.php`. Tests never touch the workbench database.

`phpunit.xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<phpunit bootstrap="vendor/autoload.php" colors="true" cacheDirectory=".phpunit.cache">
    <testsuites>
        <testsuite name="Plugin">
            <directory>tests</directory>
        </testsuite>
    </testsuites>
    <php>
        <env name="APP_ENV" value="testing"/>
        <!-- Public, testing-only key. -->
        <env name="APP_KEY" value="base64:6BDzvwO4hrN7Twv6/gaQ6oZMB/CvpUArZXho189U75E="/>
        <env name="DB_CONNECTION" value="sqlite" force="true"/>
        <env name="DB_DATABASE" value=":memory:" force="true"/>
        <env name="CACHE_STORE" value="array"/>
        <env name="SESSION_DRIVER" value="array"/>
        <env name="QUEUE_CONNECTION" value="sync"/>
        <env name="MAIL_MAILER" value="array"/>
        <env name="BCRYPT_ROUNDS" value="4"/>
        <!-- Pro, so tests can create non-admin users with permissions. -->
        <env name="CRAFT_EDITION" value="pro"/>
    </php>
</phpunit>
```

```php
// tests/Pest.php: bind with a relative path ('.'); absolute paths break on Windows across drives.
uses(Acme\Shortlinks\Tests\TestCase::class)->in('.');

// tests/TestCase.php
namespace Acme\Shortlinks\Tests;

abstract class TestCase extends \CraftCms\Cms\Plugin\Testing\PluginTestCase {}

// tests/LinksTest.php
it('redirects a shortlink', function () {
    Link::create(['code' => 'abc', 'destination' => 'https://example.com', 'statusCode' => 302]);
    $this->get('/go/abc')->assertRedirect('https://example.com');
});
```

Run `composer test`. HTTP tests run without Vite, and the base class keeps project config out of YAML files.

Cover the failure paths users hit in Craft: invalid plugin settings, a guest and an under-privileged user on each guarded route.
